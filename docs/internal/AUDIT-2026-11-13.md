# GateClerk Site Agent Audit (2026-11-13)

## 1. Summary

GateClerk (`v0.1.0`, 38 Python modules in `src/gateclerk/`, 65 test files) implements the Hikvision ISAPI read-only connector (P1), SQLite-backed site agent with per-sink fan-out and `mnotify` alerts (P2), terminal-to-terminal enrollment migration (E1), and Excel user/card import.
Despite high offline test coverage (~2,539 unit tests), **the part is NOT FINISHED for multi-site production go-live**.
Critical defects remain on the payroll path: `queue_new_events` (`src/gateclerk/agent_cli.py:369-400`) queues all stored `events` rows (including `outcome="denied"`, `outcome="info"`, and `unknown_code=1`) while the Cloud Run ingest handler (`functions/main.py:8025-8051`) only filters out blank `employee_no`, causing denied/failed auth events with an employee ID to land in Business Central as valid attendance punches.
In addition, `DeviceLoop._ensure_device_state` (`src/gateclerk/agent_loop.py:829-843`) caches the device's claimed UTC offset once for the lifetime of the daemon process, breaking event query windows by 1 hour across DST transitions on dynamic-offset terminals (`<site-b>` fw V4.13.0).
The hourly `device_users` roster push (`src/gateclerk/agent_loop.py:790-799`, `src/gateclerk/agent_push.py:1364-1381`) reads only `UserInfo/Search` (which omits `cardNo` on probed firmware) and never joins `CardInfo/Search`, so `cardNo` is always `null` in BC API Page 70641.
`doctor_cli.py:430,439` checks `chk.check == "token-refs"` (plural) while `sink_cli.py:1003,1020,1028` emits `"token-ref"` (singular), making `gateclerk doctor`'s Linux `credentials.json` fallback dead code and misclassifying missing sink tokens as exit 6 instead of exit 2.
`migrate_fingerprints.py:638-654` reads `tests/fixtures/...` relative to `__file__`, which does not exist in installed wheels or Docker images, breaking fingerprint planning in packaged builds.
Finally, `observe_skew` is never wired into the agent loop, `status/device-probe.json` and `agent.pid` have no writers, `HttpsIngestTransport` never invalidates its cached bearer token on HTTP 401/403, and PII-bearing SQLite stores/bundles/audit CSVs sit indefinitely on site hosts without retention cleanup.
